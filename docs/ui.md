# The app's look, and how to change it safely

The WPF window (`src/Elynt.App`) has one look: black, red accents, and a slow red-to-orange **accent wave** on accents
only. Spec: issue #60. Read this before changing anything under `src/Elynt.App/`.

## Where things live

- `App.xaml` merges three dictionaries, later ones winning:
  1. .NET's `Fluent.Dark.xaml` (the Fluent theme's control styles).
  2. `Theme/FluentColors.xaml`: Fluent's brushes re-pointed at the app's palette, so plain controls already match.
     Generated by `build/gen_fluent.py` (usage in its header). Regenerate it; never edit it by hand.
  3. `Theme/Theme.xaml`: every colour token and named style. The single source of truth for the look.
- `MainWindow.xaml` hosts every page: a sidebar, the page, and the detail pane on the right (layout A). Pages are
  UserControls under `Pages/`, each with the window's `MainViewModel` as DataContext (code-behind reads it as `Model`).
- `ViewModels/Sidebar.cs` lists the sidebar's pages in their groups (PLAY, WINDOWS, TOOLS) and the pinned footer: a
  new page joins its group with one line there, and gets an icon in `Theme/PageIcon.cs`. The search box at the top
  of the sidebar opens a page with a row selected through `MainViewModel.Open(PageTarget)`, which a link from one
  page to a tweak, repair tool or app on another can use too.
- `Theme/AccentWave.cs` moves the wave; `Theme/TitleBar.cs` paints the title bar.
- `Assets/elynt.ico` is the app's red "E" icon (the window, taskbar, tray and Start menu). `build/gen_icon.py` draws it
  (usage in its header). Redraw it there; never edit the .ico by hand.

## Using the theme

Take colours and styles from `Theme.xaml`. When a page needs a style another page could use, add it to `Theme.xaml`
rather than to the page's resources (CI fails on a colour outside `Theme/`).

- **Colours:** `Theme.Bg` `Theme.Surface` `Theme.Surface2` `Theme.Hover` `Theme.Stroke` `Theme.StrokeStrong`
  `Theme.ControlEdge` (an off switch's edge) `Theme.Code` `Theme.Text` `Theme.TextBody` `Theme.TextDim` `Theme.TextFaint`
  `Theme.Red` `Theme.RedHover` `Theme.RedText` (red text on `RedTint`) `Theme.Orange` `Theme.RedTint` `Theme.RedEdge`
  `Theme.OrangeTint` `Theme.OrangeEdge`, and `Theme.Good` for the connection dot only. Text reads at 4.5:1 or better on
  every background, `TextFaint` included; keep it that way.
- **Accent wave:** `{DynamicResource Theme.AccentWave}`, always DynamicResource (AccentWave swaps in the moving brush at
  run time; a StaticResource keeps the still one). Only on accents: switches that are on, meters, the selected row's
  edge, the top strip, Home's big numbers. Button faces use its twin `Theme.ButtonWave` (through `Button.Primary`),
  which turns a darker orange so white labels stay readable; it moves in step. Text, backgrounds and cards stay plain.
- **Text:** `Text.H1` (page title, set by the window), `Text.H2`, `Text.Body`, `Text.Dim`, `Text.Label` (small-caps
  heading: write the text in CAPITALS), `Text.Icon` (Segoe Fluent Icons glyphs), `Text.Lock` (the lock glyph a locked
  switch and a protected service show), `Text.Message` (the answer to the last action; takes no room while empty),
  `Link` (a Hyperlink). Nothing smaller than 12 px, Windows' smallest text.
- **Boxes:** `Card`, `Pill` (sets its text to 12 px: leave the TextBlock's size unset), `Pill.Warning` (orange: a risk),
  `Pill.Danger` (red: "Destructive", "Can't be undone"), `ReversibilityPill` + `LockPill` (a tweak's reversibility and
  lock, danger or plain), `RestartPill` + `RestartPillText` (a repair tool's restart need), `WarningBox` (orange: read
  this first), `DangerBox` (red: can't be undone), `CodeBox` (monospace).
- **Lists:**
  - `CardList`: a ListBox of `Row` cards (hover shade, red edge when selected, text wraps). Any list of things.
  - `CardRows` + `CardRow`: readouts inside one card, split by faint lines (sensor values, BIOS settings).
  - `Table.Header` + `Table.Row`: a table on the page (Undo history, drift). `Table.List` + `Table.ListRow` for one
    long enough to virtualise (the services).
- **Controls:** `Switch` (a CheckBox as an on/off switch; give a locked one `theme:Switch.IsLocked="{Binding IsLocked}"`
  so it shows a lock rather than fading like a busy one), `Button.Primary` (button wave), `Button.Destructive` (red),
  and a plain Button as the secondary form. One strong button (primary or red) per screen at most, for the next step:
  a rare action, or one guarded by its own confirmation (Scan, Delete, Restore everything), stays plain. `SearchBox` (a
  TextBox with a search glyph) for every search and filter: its `AutomationProperties.Name` is also the hint text shown
  while it's empty, so give it one, and put the result count just under it ("12 apps"). `Meter` (thin ProgressBar,
  Maximum 1). `NavItem` (sidebar). Plain TextBox, ComboBox, CheckBox, TabControl, ProgressBar, ScrollBar, ToolTip and
  ListView already match through FluentColors.xaml.
- Dim text with `Text.Dim` or `Theme.TextDim`, never with Opacity.

## Sizes

The window opens at 1600×1000 (or the screen, if smaller), can be resized, and never remembers its size. Its minimum is
900×520, where everything must still be usable. Below 1200 px wide it goes **compact** (`MainWindow.IsCompact`): the
sidebar folds to its icons and the detail pane narrows from 400 to 320.

- Rows wrap their text; the switch or buttons on a row's right stay visible at 900 px, with no sideways scrolling.
- Page content sits in the margin the window gives it (32,26,24,0). Row cards: Margin 0,0,0,6, Padding 16,12,
  CornerRadius 8.

## Checking a change: the screenshot tour

WPF can't run on Linux, so a cloud session can only compile the XAML. The real check is CI's screenshot tour
(`tests/Elynt.App.Screenshots`, workflow `ui-screenshots.yml`), which runs on every push that touches the app, the
sample PC or the fakes:

- It opens the real window against a made-up PC (`tests/Elynt.Core.Tests/SamplePc.cs`) and shoots every page, every
  other tab, every fold opened and the detail pane at its fullest, at 1600×1000, 900×520 and 2560×1400.
- **Any WPF binding error fails the run.** They fail silently in the app, so check every `{Binding X}` against the view
  model it reads from before pushing.
- The pictures go to the branch `screenshots/<branch>`. Look at them:
  `git fetch origin screenshots/<branch>` then `git archive FETCH_HEAD | tar -x -C <empty folder>`.
- A row template is only drawn when its list has rows. Give a new list rows on the sample PC (`SamplePcTests` keeps
  every list at two or more), and a new page state a step in the tour's `ShowEveryStateAsync`.
